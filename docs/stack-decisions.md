# DMR Online — Stack Decisions

Status: agreed on 2026-11-15, updated the same day (auth library, units, language, editing after submit). Companion to `DMR_Workbook_Analysis.md` (what the old workbook does) and `12-roadmap-and-release-plan.md` (when each part is built).

Scope assumption: this is the **web version, online only**. Offline use and sync are out of scope for now.

## Final stack

| Layer | Choice |
|---|---|
| Infra | Docker, Nginx |
| CI/CD and tooling | GitHub Actions, Biome, `bun test` |
| Runtime and package manager | Bun (monorepo workspaces) |
| Web container runtime | Node (Bun is used for install and build only) |
| Frontend | Next.js as a frontend only (client-side pages), TypeScript |
| UI | shadcn/ui, Tailwind CSS |
| Data fetching | Eden Treaty (`@elysiajs/eden`) called inside TanStack Query |
| Tables | TanStack Table |
| Forms | TanStack Form, validated with the shared zod schemas |
| Backend | Elysia |
| Validation | zod (through Elysia's Standard Schema support) |
| Database | PostgreSQL, `pg` driver |
| ORM and migrations | Drizzle ORM, drizzle-kit |
| Logging | logixlysia |
| Auth | better-auth (session in an httpOnly cookie) with RBAC — built in v0.9.0 |
| PDF | Gotenberg (headless Chromium in its own container) — v1.1.0 |
| Excel | exceljs, in the browser — v1.1.0 |

## Removed from the first proposal

| Package | Why |
|---|---|
| `axios` | Replaced by Eden Treaty. Route types reach the frontend with no hand-written response types. |
| `jose` | Replaced by better-auth. |
| `uuid` | Not needed. IDs are generated by the database default (`gen_random_uuid()`); Bun also has `crypto.randomUUID()` and `Bun.randomUUIDv7()`. |

## Deferred

| Topic | Decision | When |

| Auth implementation | Library decided: **better-auth**. `jose` is not used. Implementation waits for its version. | v0.9.0 |
| Persian (Jalali) calendar | English UI and Gregorian dates for now. | a later release (proposed v1.2.0) |
| Rounding rule | Follow the workbook for now. Review later. | v0.8.5 |

## Product decisions that shape the code

| Topic | Decision |
|---|---|
| Units | Values are **stored in SI**. Display units are a setting of the project (default SI; a preset reproduces the workbook's units). Conversion happens only in `packages/calc/units`. |
| Language and calendar | Everything in English, Gregorian dates. |
| Editing | A report **can be edited after submit**. An edit raises its revision, rewrites its stored result and triggers recalculation of later reports of the same well. |
| Tenancy | One company; many projects and wells. |
| Mud systems | Water-based and brine first; oil-based later. |

## Conditional

- **Zod schemas from Drizzle tables:** on Drizzle v1 import from `drizzle-orm/zod`; on the 0.x line install the separate `drizzle-zod` package. Do not install both.

## Conventions that follow from these choices

1. **One domain behind Nginx.** `/api/*` goes to Elysia, everything else to Next.js. No CORS, and the httpOnly cookie works without extra settings.
2. **Shared workspace packages.**
   - `packages/schemas` — zod schemas used by TanStack Form on the frontend and by Elysia routes on the backend.
   - `packages/calc` — the calculation engines as pure functions (volumes, inventory maths, rheology, solids, hydraulics, hole cleaning). The frontend uses them for live preview; the backend uses them for the stored result.
3. **Zod in Elysia does not coerce types by itself.** Use `z.coerce.number()` and similar for `params` and `query`.
4. **IDs** are `uuid` columns with a database default.
5. **Number columns.** `numeric` for stock quantities and money; `double precision` for measurements (SI) and engine inputs. Drizzle returns `numeric` as a string, so convert at the repository boundary.
6. **Rounding (until v0.8.5).** Engines calculate in the workbook's units with the workbook's constants, behind SI adapters, and must reproduce the workbook's numbers at the precision the workbook displays. Where a full-precision calculation gives a different displayed digit, copy the workbook's intermediate rounding for that step and leave a comment.
7. **Report output.** The DMR and inventory pages have a print stylesheet (`@media print`, A4; the inventory in landscape). Since v1.1.0 the API returns the same pages as PDF through Gotenberg (`GET /reports/:id/pdf`), and the browser builds Excel files with exceljs from the same data and the same `lib/format.ts` conversions as the screen.
8. **Tests.** Every function in `packages/calc` has `bun test` cases taken from the workbook's values. CI runs Biome and the tests on each push.
9. **Before auth exists (before v0.9.0).**
   - Do not expose the app to the public internet.
   - Add nullable `created_by` / `updated_by` columns from the first migration, so RBAC does not need a data migration.
   - Put a single guard hook in the Elysia app (it allows everything for now), so that RBAC is added in one place.
